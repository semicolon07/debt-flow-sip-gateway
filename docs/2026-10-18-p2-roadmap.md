# Debt Flow SIP Gateway — P2 Candidate Roadmap

วันที่: 18/10/2026

สถานะ: **Draft for prioritization — ยังไม่เริ่ม implementation**

## 1. เส้นแบ่งระหว่าง P1 release กับ P2

P1 engineering scope ปิดแล้ว แต่รายการใน `pilot-acceptance-matrix.md` ยังต้องผ่านก่อน production rollout
โดยเฉพาะ Windows Server/IIS/Issabel จริง, signed package, browser/device matrix, 250 sessions,
200 concurrent calls และ soak test รายการเหล่านี้เป็น release qualification ของของที่สร้างเสร็จแล้ว
ไม่ใช่ feature ใหม่ของ P2

แนะนำ rollout แบบมีจุดหยุดและ rollback ชัดเจน: internal test → 10 users → 50 users → 200 users
โดยต้องผ่าน acceptance criteria ของแต่ละช่วงก่อนขยายกลุ่ม

## 2. เป้าหมาย P2 ที่เสนอ

P2 ควรขยับจาก single-node production-oriented MVP ไปสู่ระบบที่ทนต่อความขัดข้อง, อัปเกรดได้โดย
ลด downtime และรองรับรูปแบบเครือข่ายจริงที่หลากหลายขึ้น โดยยังคงหลักว่า Gateway ไม่เชื่อม Web API
โดยตรง และ browser เป็นผู้ relay capability/event เหมือน Desktop Agent

### P2.1 High availability และการบำรุงรักษา

- รองรับอย่างน้อย 2 Gateway nodes พร้อม health-aware routing และ session affinity
- กำหนด ownership ของ SIP registration, browser session และ call ให้ไม่เกิด duplicate REGISTER/INVITE
- graceful drain: หยุดรับ session/call ใหม่ แต่ปล่อย active call จบก่อน shutdown
- rolling upgrade และ rollback โดยไม่ตัดสายที่อยู่บน node อื่น
- recovery contract เมื่อ node ที่ถือ active call ล่ม โดยระบุให้ชัดว่า P2 รุ่นแรกอาจกู้สายเดิมไม่ได้
  แต่ต้อง reconnect และพร้อมโทรสายใหม่ได้ในเวลาที่กำหนด

### P2.2 Network และ media hardening

- TURN over TLS บน TCP 443 สำหรับเครือข่ายที่บล็อก UDP/TCP 3478
- ICE restart, RTCP/QoS metrics, packet-loss/jitter alarms และ capacity protection ต่อ node
- SIP TLS/SRTP ระหว่าง Gateway กับ PBX หาก security policy หรือ topology ต้องการ
- ทดสอบ NAT, VPN, WARP และ restrictive corporate network เป็น matrix ที่ทำซ้ำได้

### P2.3 Browser recovery และ ownership

- idle-session recovery หลัง refresh โดยไม่ REGISTER ซ้ำหรือทิ้ง stale ownership
- multi-tab arbitration ให้มี tab เจ้าของโทรศัพท์เพียงหนึ่ง tab
- ศึกษา in-call media reattachment หลัง refresh/network switch; แยกเป็น optional milestone เพราะ
  ต้องออกแบบ signaling, ICE restart และ security binding เพิ่ม ไม่ควรสัญญาว่ากู้สายได้ก่อนพิสูจน์

### P2.4 Advanced telephony

- hold/resume
- blind transfer และ attended transfer
- queue/presence integration เฉพาะเมื่อมี contract จาก PBX และ product flow ที่ยืนยันแล้ว
- call recording แยกเป็น security/legal workstream: consent, encryption, retention, access audit และ storage
- conference, whisper, monitor และ barge-in จัดเป็น backlog หลัง hold/transfer

### P2.5 Codec และ capacity

- เพิ่ม transcoding เฉพาะเมื่อจำเป็นต้องรองรับ codec นอก PCMU/PCMA
- benchmark CPU/memory/latency ก่อนเลือกว่าจะทำใน Gateway หรือแยก media worker
- ทำ distributed load/soak/failure test ที่ 250 sessions และ 200 concurrent calls เป็นอย่างน้อย
  พร้อมหา safe operating limit ของ hardware จริง ไม่ใช้ hard limit เป็น capacity guarantee

### P2.6 Operations และ security

- zero-downtime capability-key/certificate rotation
- node/call/session dashboard, SLO, alert tuning และ capacity forecast
- chaos/recovery drills: process crash, node loss, PBX outage, TURN exhaustion และ database corruption
- automated release evidence, signed installer, SBOM/vulnerability/license gate และ rollback rehearsal

## 3. ลำดับที่แนะนำ

1. ทำ P1 production release qualification และ controlled rollout ให้จบก่อน
2. P2.1: HA, session ownership, drain และ rolling upgrade
3. P2.2: TURN/TLS 443 และ network/media hardening
4. P2.3: refresh/reconnect/multi-tab recovery
5. P2.4: hold และ transfer
6. recording, transcoding และฟีเจอร์ call-center ขั้นสูงตาม business priority

ไม่แนะนำ automatic fallback จาก Gateway ไป Desktop Agent ระหว่าง active call เพราะอาจสร้าง SIP dialog,
event timeline และ media ownership ซ้ำซ้อน หากต้องมี fallback ให้เลือก runtime ก่อนเริ่ม session/call และ
แสดงผลให้ผู้ใช้/ผู้ดูแลทราบอย่างชัดเจน

## 4. Definition of done เบื้องต้นสำหรับ P2

- rollout/rollback และ node-drain procedure ผ่านบน Windows Server จริง
- 2-node topology ไม่เกิด duplicate SIP registration, command หรือ API call event
- node หนึ่งหยุดทำงานแล้วผู้ใช้ที่ไม่ได้อยู่ใน active call กลับมาพร้อมโทรได้ภายใน SLO ที่ตกลง
- rolling upgrade ไม่ทำให้ call setup ใหม่ล้มเหลวเกิน error budget ที่ตกลง
- load/soak ผ่านที่ 250 sessions / 200 concurrent calls รวมทั้ง cluster พร้อม capacity headroom
- network matrix รวม direct ICE, TURN UDP/TCP และ TURN/TLS 443
- security, observability, incident/rollback runbook และ release evidence ได้รับอนุมัติ

ค่า SLO, hardware profile, topology ของ PBX และรายการ advanced telephony ต้อง confirm ก่อนเปลี่ยนเอกสารนี้
เป็น committed P2 implementation plan
